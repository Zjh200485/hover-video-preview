# 悬停视频预览扩展 2.3

继续使用当前文件夹，无需移除扩展或再次“加载解压缩的扩展”。本次代码升级后，在旧扩展面板点击一次“重新载入扩展”以载入 2.3，再打开面板连接视频。也可按 Alt+Shift+R；这一步用于载入新版代码，不是日常断线恢复步骤。必须同时运行本次配套更新的桌面程序（接收协议 3）。重启桌面程序后请复制新连接码。

## 以后使用

先启动原来的桌面程序，在视频页播放视频，打开扩展并点击“开始预览”。扩展会记住连接码，导入操作不需要重复。

- 桌面接收器临时不可用时保留现有采集、持续重试，恢复后继续送出画面，不再因连续失败一分钟而自行断开。
- 后台采集页面失效时会尝试恢复此前主动选择的视频标签页，不会改为采集你正在浏览的其他页面。采集页面完全丢失时，定时检查的正常周期为一分钟；系统休眠或浏览器调度可能延后。
- 重连前等待旧采集流释放，避免旧流仍占用时立即申请新流而失败。
- 点击“停止”、浏览器停止共享、关闭视频标签页后，不会主动绕过你的停止操作继续采集。
- 内部播放意外暂停时自动尝试恢复；持续无法推进的视频时钟会被判为异常，避免反复上传旧帧却显示正常。
- 人工切换视频失败时，取消旧视频的自动恢复请求，避免意外跳回上一个视频。
- 帧传输带有会话和序号；已经停止或被新会话替换的帧，以及乱序旧帧，不会重新写入桌面预览。

浏览器完全退出、网站导航导致授权失效或浏览器撤回采集授权后，需要回到视频页点击“开始预览”或“修复并重连”，无需重新导入扩展。桌面程序每次启动会更换连接码，重启后仍须复制新码。扩展不能用旧码连接新的接收器。

## 验证及边界

验证脚本和说明保存在新版 GitHub 仓库中。本地运行目录清理后仅保留运行文件及使用说明。自动化验证使用独立 Edge 配置及本机测试接收器；它不能证明所有视频网站或当前电脑的所有节能设置下永不冻结。若仍有异常，面板中的错误信息可区分授权失效、连接码失效与采集无响应。

对照的开源实现：[Google 官方后台标签页采集示例](https://github.com/GoogleChrome/chrome-extensions-samples/tree/main/functional-samples/sample.tabcapture-recorder)。未引入额外运行依赖，也没有复制示例中的录像和下载功能。
